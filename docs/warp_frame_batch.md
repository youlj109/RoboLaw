# 整帧 Warp CUDA 并行查询

HS、PT 与 RS 先根据当前实测状态登记查询，再通过同一个 `GeometryBatch` 队列执行，全部完成后才形成该时刻的风险特征。动作、标签仍为 30 Hz，物理和接触流仍为 120 Hz。不会用未来姿态计算当前标签，也不会跳过来不及计算的帧。

## 调度和 GPU 实现

- 每个最小距离请求保持按保守包围盒下界排序的候选。每轮从所有请求的前沿预取 8 个候选；只用下界筛选，最终结果仍为完整三角网格距离。
- 对同一轮涉及的所有网格对展平三角形任务，在一个 CUDA 网格中并行执行。距离查询与 RS 相交查询共用这轮调度，碰撞布尔值在 GPU 归约，避免逐三角形回读。
- 使用常驻 GPU 网格/BVH、可增长的缓冲区和固定页主机传输缓冲区。每轮通过 CUDA Graph 执行重置、距离上界种子、完整三角查询、分块归约和结果整理。
- 每轮统一回读所需结果，每个查询 7 个浮点数。依赖上一轮精确最小值的候选剪枝可能需要多轮；不能宣称整帧永远只有一次同步。
- 完全相同的网格对姿态可复用结果；任一姿态改变即使缓存失效。GPU 非有限输出或查询异常保留未知，不退回 bbox、采样点或 CPU/FCL。
- 多候选结果按原顺序消费，保留相等距离时的碰撞体选择。阈值、豁免、PT v4、已知结果判级和 IR disabled 不变。

运行记录中的 `distances.gpu_batch` 保存前沿宽度、轮数、提交对数、真实 GPU 查询数、统一回读次数、Graph 启动次数和队列墙钟时间。`warp_batch.RUNNER.stats` 保留累计计数。

## 参数与复现测量

`ROBOLAW_WARP_BATCH_FRONTIER` 可覆盖每请求的候选前沿宽度，默认 8。更大并不一定更快：会计算更多本可被后续精确最小值剪掉的网格对，增加显存、计算和传输。当前不是为了占满设备而增加无效查询。

```bash
PYTHONPATH=. ROBOLAW_WARP_BATCH_FRONTIER=8 .venv-arena/bin/python \
  scripts/benchmark_warp_frame_batch.py \
  --episode /absolute/path/to/recorded_episode \
  --cache reports/warp30_mesh_cache \
  --frames 0,256,573,1146,1719,2291 --rounds 2 \
  --output reports/warp_frame_batch_benchmark.json
```

测量使用记录的机器人、瓶子、碗和厨房关节物体姿态，以及按指纹索引的完整碰撞网格。scalar 路径保留原有逐对执行作为对照。检查各分项距离、最近碰撞体身份、表面相交标志、最近点有效性及自碰撞对一致性。它测量几何部分，不等于完整采集速度，不等于整段新视频已经采完。

`nvidia-smi` 的利用率包含设备上其他进程，且是采样窗口内的活跃时间指标，不能代表所有 SM 的运算效率。测量同时记录延迟、回读次数、功耗和显存，不以利用率百分比单独判断优化成败。

## 2026-10-22 实测

RTX 5090，同一条人体芥末瓶轨迹均匀抽取 32 个时刻、各两轮，共 64 次整帧几何评价：旧路径平均 1565.35 ms，新路径平均 220.86 ms，提升 7.09 倍；P95 从 1835.16 ms 降至 258.61 ms。旧路径统一计数为 20648 次逐对回读，新路径 352 次批量回读（平均每帧 5.50 次）。选取位置上的最大距离差为 0 m，覆盖、自碰撞、最近碰撞体和相交标志一致。

前沿宽度 1/4/8/16 均作测量，当前场景选取 8；更宽的 16 需要更多精查，反而变慢。完整结果保存在 `validation_warp_frame_batch_20261022.json`。

该次批量测量的整卡 nvidia-smi 利用率平均 66.3%，峰值 92%，显存峰值 3073 MiB。没有实现或声称持续 100% 利用率；旧路径利用率也曾到 100%，但耗时更长。当前收益以实测延迟和减少等待衡量。
