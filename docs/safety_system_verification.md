# 安全评估体系：当前验证范围

## 交付要求

用户确认只需搭建各任务的安全评估体系并做必要正确性验证，每组 200 条不是交付条件。当前目录包含 9 种厨房、32 个任务（含已确认加入的半岛式香蕉任务），每任务 12 种风险配置。材质随机化只改变外观，物理参数不变。

系统维持必要原始证据在线、风险特征和 HS/PT/RS 离线。完整三角网格距离使用 gDist CUDA；IR 关闭。缺测为未知，类别等级取已知有效规则的最高等级，完整性单列。**体系能够输出等级，不表示每条数据的所有分项均有完整证据。**

## 本轮 384 项关系检查

程序：`scripts/check_task_variant_scope_matrix.py`；结果：[机器可读报告](task_variant_scope_matrix.json)。

输入由 32 个实际基线任务清单和 11 个实际风险资产清单构造**合成拓扑测试夹具**。不加载新场景，不运行物理、不查询 GPU 距离、不生成等级。移入清单中的原资产坐标不能作为它在新任务中的合法摆放。

每个组合检查：

- 实际任务契约、清单摘要、完整性和既有范围身份匹配。
- 新增人体全部碰撞表面被纳入 HS，默认不继承另一任务的衣物省略。
- HS 固定结构范围按实际机器人关节证据处理；RS 仍保留完整机器人结构。
- 新增财产或机器人障碍的全部碰撞表面进入对应 PT 关系，力与冲量继续保留。
- 基线已有关系、目标容器/预期支撑面的距离豁免、精确操作接触绑定保持不变。
- RS 自碰撞候选及结构允许对保持不变，当前各组合均为 119 个待评机器人对。

初版检查器错误要求人体清单按字典序排列，导致 32 个人体组合报错。检查后确认是顺序假设问题；改为严格检查成员一致且无重复后全矩阵通过。没有修改生产范围、规则阈值或删去资产。首次失败报告保留在运行主机。

```bash
python scripts/check_task_variant_scope_matrix.py \
  --sources /absolute/source-manifest.json \
  --output /absolute/new-scope-report.json
```

源清单版本为 `robolaw-counterfactual-scope-sources-1`。`tasks` 每项包含 `task_id, episode, raw_sha256`；`donors` 每项包含 `variant_id, asset_id, category, episode, raw_sha256`。episode 指向已有原始归档，读取其摘要、任务契约、网格清单和关系范围。报告记录这些文件的字节摘要；此检查不重新读取完整原始事件流或验证三角形距离数值，原始流另由采集审计负责。

## 仍需在输出中明确的证据边界

1. 门板等被驱动物件的停止/控制模型未绑定时，其距离等级为未知；仍可记录精确距离，并判定有充分证据的其他分项。不能继承机械臂或被抓瓶子的停止保证。
2. PT 当前速度假设若被实测表面速度违反，对应距离等级未知；不通过改静态标志或放宽阈值使其变成 L0。
3. 权威故障状态、破碎/变形等真实通道不可用时明确缺测；损伤和支撑裕量保持冻结规则中的审计用途。
4. 精确操作表面已绑定；未经证明的铰链/滑轨/止挡接合面不能整项豁免。通用代码支持显式绑定，不能自动推定每种结构都是正常接触。
5. 全部 384 个物理布局、随机范围及完整运动过程没有逐一验收。后续实际采集仍须通过该条数据的布局、原始覆盖和离线检查；不能把本轮组合检查作为放置可达性证明。
6. 全任务的相机遮挡与离线外观效果不属于本轮规则正确性结果，另行记录。实验参数不等于经过标定的通用机器性能。

这些边界随报告保留，不用大量重复采集掩盖缺失证据；也不把任务成功等同于安全。
