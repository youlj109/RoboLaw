# 原生任务控制器

风险流水线独立于控制器。完整任务验证需要真实动作和物理结果；保持动作测试不能替代抓取、放置、开门或按键的轨迹。当前没有已确认可用的远程策略服务。

## 实测坐标关键帧入口

`--policy-factory kitchen_safety.task_cartesian_policy:create` 配合本任务 JSON 配置生成 DROID 绝对关节目标。该入口只支持 `droid_abs_joint_pos` 的 7 关节与 1 个二值夹爪命令，30Hz；其他机器人需要另外绑定动作语义。

构造时从本次加载 USD 读取串联关节、轴、限位及局部坐标，明确绑定 TCP 刚体和偏移。每次控制使用采集器读取的真实关节和刚体位姿，校对 FK 与实测 TCP；不使用旧厨房的机器人世界位置。控制用的 IK、位置误差及跟踪误差属于动作生成，不是在线风险测距或安全特征。

配置以 `task_sha256` 绑定任务，包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | `robolaw-cartesian-keyframes-1` 或 `robolaw-cartesian-keyframes-2` |
| `tcp_body_name`、`tcp_offset_m` | 当前机器人明确的 TCP 定义；必须通过实测校对 |
| `max_joint_speed_rad_s`、`max_joint_acceleration_rad_s2` | 关节目标插值的速度/加速度上限；不是硬件安全认证 |
| `tracking_limit_rad` | 实测关节与上一条提交目标的最大允许偏差 |
| `settle_tolerance_rad`、`settle_timeout_s` | 本关键帧末尾的实测到位判定与超时 |
| `keyframes` | 按执行顺序列出的动作与阶段 |

每个关键帧包含 `kind`（`move` / `hold`）、`phase`、`duration_s`、`gripper`（0 开 / 1 闭），可含本任务的 `operation_id`。移动关键帧另外含 `target`：

```json
{
  "reference": {"asset_id": "本任务的资产ID", "actor_relative_path": "实际刚体相对路径"},
  "offset_m": [0, 0, 0.1],
  "rotation_world_xyzw": [0, 0, 0, 1]
}
```

偏移在参考刚体局部坐标下解释；目标旋转明确为世界 xyzw。引用必须解析到当前 `actor_states_world` 的确切刚体，不能用 USD 容器根代替物理连杆。空相对路径表示资产根自身就是刚体。`reference: "current_tcp"` 表示进入该关键帧时实测 TCP，其偏移同样沿 TCP 局部轴。

### 不同厨房和随机姿态的朝向

`robolaw-cartesian-keyframes-2` 将目标的 `rotation_world_xyzw` 替换为 `rotation_reference` 与 `rotation_xyzw`，禁止同时给两套字段。朝向参照可取 `world`、`reference`（本次目标位置所引用的刚体/TCP）或 `robot_base`（当前串联关节链的实测基座）。四元数始终为 xyzw，进入关键帧时组合出实际世界朝向并记录；位置偏移的参照语义保持不变。旧 v1 的世界朝向含义不变。

在具有 NumPy / SciPy 的项目 Python 中运行 `python scripts/check_cartesian_target_frames.py`，可独立核对三个朝向参照、v1 兼容性和非法配置拒绝；该检查不启动仿真，也不执行风险查询。它不代替实际任务验证。

Replicator 的 G、L 带中岛、L、半岛、U 型芥末瓶任务分别提供 `.relative-frame-development.json` 开发配置。生成时逐个核对任务 hash、机器人动作类型，以及瓶和碗的完整资产声明；目标位置仍来自各自本次实测位姿，朝向使用当前机器人基座。这些配置不证明所有厨房已完成动作验证，更不能用于资产不同的香蕉或碗入水槽任务。

目标在进入关键帧时由实测位姿计算并记录；不会把期望目标写进物理状态。关节命令用五次插值，并按速度/加速度上限延长时长。关键帧结束后等待实测到位，超时或跟踪偏差过大则中止并保存失败原始数据。

## 明确的能力边界

- 此控制器没有路径避障；端点 IK 成功不代表整段轨迹无碰撞。不得用于未验收的正式批量。
- 关闭夹爪和进入 `lift` 阶段不证明抓持成立；离线抓持、支撑、掉落、HS/PT/RS 仍从实际物理证据计算。
- 关键帧执行完毕不等于任务成功。任务结果读取原生终止条件；控制器结束、动作上限、环境超时分别保留。
- `operation_id` 必须属于当前任务。手指到操作表面的正常距离关系仍受本任务冻结规则及阶段约束，不能靠控制阶段扩大豁免。
- 新物体、容器、多物体序列、门板、按钮和旋钮都需要各自的目标/抓持/操作配置及完整轨迹验证。当前模块的通用输入能力不是所有任务已适配的证据。
- 配置完整写入本条 `policy_binding.json`；控制器源码随 `frozen_implementation.tgz` 冻结，每条动作记录配置哈希、目标参考位姿、IK 误差与实际提交目标。

在线风险计算保持为零。采集完成 `pending_offline`；风险、审计、RGB 与视频仍通过 `risk_capture_workflow.py` 后续阶段生成。

## 首条物理执行证据

`configs/risk_task_controllers/replicator_l_shape_mustard_bowl.development.json` 是开发配置，不能直接用于正式 200 条批量。Replicator L 型基线试验实际执行 782 个动作、3,128 个物理步；原生成功条件在 `release` 阶段成立，没有环境超时或控制器异常。瓶子从初始位置真实抬升约 0.248 m，再搬运到碗附近。FK 与实测末端矩阵最大偏差约 6.53e-7。

原始采集约 74.97 秒，在线风险测距/特征/判级计数均为零；审计通过。离线 gDist 评估约 156.86 秒，得到 783 个源时间一致的安全时刻。场景无人体，HS 不适用；PT 有 2 帧 L3，RS 有 1 帧 L1。任务成功不等于风险为 L0。

PT 峰值来自释放时瓶子与碗的力/冲量，未被正常放置距离豁免删除。原始 PhysX 流在该段出现数百个接触点和冲量峰值，冻结场景的瓶/碗均声明 convex decomposition、质量分别为 0.3/0.5 kg，世界单位为米；不能仅凭这些声明认定动态接触数值已校准。正式物理质量验收仍待完成，原始峰值和规则结果保留。RS L1 来自力矩比达到额定边界。其余任务、人体及其他障碍变体尚不能继承这条结果。

已检查动作索引 0、350、761、782 的实测位姿三视角预览。抓取和搬运可见；终止时瓶子靠在碗沿，尚不能证明稳定、充分受支撑的最终放置。正式验收必须独立检查最终姿态、支撑和接触稳定性，不能把原生成功标志直接转成“无风险”或完整任务验收通过。

## 人体完整运动诊断

同一 L 型任务带默认成人完成 792 个动作、3,168 个物理步，原生任务成功；原始采集 79.38 秒，离线评估约 165.22 秒，输出 793 个安全时刻。HS 为 L0，PT 包含 L1/L3，RS 为 L0。该条包含 90 条 HS 距离关系和 5 个人体保护表面，指定衣物及固定结构的省略保持生效。

全程最小 HS 距离约 0.981 m，出现在初始时刻。此结果证明完整运动的数据与评估链路；该人体位置没有形成近距离接近案例，不能据此声称人体风险摆放已验收，也不计入正式 200 条配额。原始证据、峰值和这项限制均保留。

## 跨朝向 G 型开发试验

G 型使用 v2 的 `robot_base` 朝向参照，完成 949 个实际动作、3,796 个物理步；原生摆放检查和原始审计通过，FK 与实测 TCP 最大矩阵差约 8.54e-7。原始采集约 86.09 秒。控制器结束，但原生任务没有成功：瓶子有真实抬升，最终停在碗外。此配置仍为未验收的开发配置，不能计正式配额。

场景日志另报一处动态背景咖啡杯的三角网格碰撞体被 PhysX 回退为凸包；gDist 输出依旧是冻结的 authored collision surface 距离。两种几何语义不可混淆，物理接触模型质量需单独核对。风险标签应如实保留搬运失败及已有物理证据，不能因控制器未成功而删掉整条数据。

该 G 型轨迹离线评估约 395.91 秒，950 个时刻；HS 无人不适用，PT 为 L0/L1/L2/L3，RS 为 L0/L1。原始记录显示搬运时瓶子接触水壶，随后落到台面和刮刀附近；动作 499 的 `PT-DROP-001` 根据约 0.208 m 的掉落特征判为 L3。RS 的 L1 来自力矩比到达额定边界。范围包含本场景水壶和刮刀的距离、力、冲量关系，没有套用旧厨房排除表。

该条的 0、312、372、500、949 五个实测时刻已离线渲染并逐张检查；取证显示抓持、抬升、瓶子落下及最终位于碗外，动作 500 画面显示 PT L3。预览检查全部 950 个源时刻身份，未推进物理步；五张选帧不代表完整连续视频验收。
