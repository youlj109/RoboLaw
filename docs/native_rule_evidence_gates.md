# HS/PT/RS 判级输入与证据校验

## 交付范围

当前目标是安全评估体系及必要的正确性验证。没有每组 200 条的采集要求；控制器成功率优化、生产配额不作为本次规则修复的验收条件。规则正确性与测量覆盖必须分开：合法已知分项取最高等级，缺测保留未知，不以整体 L0 表示全部证据齐全。

## 本次修复

原生 `TaskRules` 现在校验实际几何证据，不能把配置中的 gDist 名称写到任意输入上并当作合法距离。

- HS/PT 检查实际 metric、complete、距离值一致性、有限非负数、来源碰撞表面、目标表面及完整有效目标集合。
- HS 检查运动体/人体身份、表面速度和静止状态；PT 检查两端速度满足冻结 profile 的假设。非法距离只使距离分项未知，已确认的接触/力风险仍参与最高等级。
- PT 缺少已声明关系或 payload 时生成相应未知分项和缺测原因；重复、未声明身份直接拒绝。
- 操作距离省略必须匹配本条冻结操作编号、阶段、来源、目标表面及声明摘要。伪造省略或阶段不符直接拒绝。合法距离省略继续保留力和冲量规则。
- HS 动态 SSM、PT v4、RS 数值边界、统计窗口、已知结果聚合和 IR 禁用均未改变。

这些校验不是密码学来源证明，必须与原始归档、源代码/几何/backend 哈希校验一起使用。

## 可复现规则检查

在项目已安装依赖的 Python 环境执行：

```bash
python scripts/check_native_rule_contract.py \
  --cases configs/risk_conformance/portable-cases.json \
  --output /tmp/native-rule-contract-new.json
```

输出路径必须不存在。调用实际生产 `TaskRules`、聚合器及一个明确标记的历史场景豁免包装器；58 个可迁移边界案例加 24 个无效证据/范围/已知风险案例，共 82 项。规则输入 fixture 不证明实际网格查询精度或新场景覆盖。`distance_queried`、`distance_field_emitted` 由几何/特征边界检查负责，规则检查不会声称测试了它们。

首轮 11 个非法证据反例在旧实现中全部错误返回距离 L0；新实现保留对应未知。增加后的 82 项全部通过。

## 已有数据只读比较

使用 `scripts/compare_native_rule_results.py`，显式指定候选源码、原始 episode、已有离线输出和新报告路径。这是新规则的兼容性诊断，不是历史冻结版本复现；不写回原始标签，不运行仿真或 GPU 测距。

- 人体芥末瓶完整记录：793 个时刻，所有规则等级及类别等级一致。
- 最新固定组件柜门探针：7 个时刻，等级一致，条件距离省略与接触规则保留。
- 较新的 11 个 articulation 操作探针：77 个时刻，等级一致。
- 32 个历史保持探针：128 个时刻中，25 个任务完全一致；7 个较早任务缺少 `effective_target_colliders` 元数据，新校验将相关 PT 距离保留未知。旧数据与旧标签未修改；不能补造目标覆盖清单，也不能宣称 32 个历史任务全部兼容。

旧数据仍使用自己的冻结实现回放；要采用新校验须显式迁移并独立保存完整证据。上述比较只证明输入与规则兼容，不替代几何准确性、原始测量或完整任务运动验证。

## 尚有明确边界

门板等被驱动连杆没有经绑定的停止/控制模型时，对应距离分项仍未知；不能继承机器人制动参数。缺少权威故障状态、损伤证据继续保留缺测，支撑裕量/损伤仍按当前 v4 作为审计项。未固定的铰链、滑轨和止挡不能整体豁免。当前实现及实验阈值不构成真实设备安全认证。
