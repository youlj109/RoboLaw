# gDist 完整网格测距的容量保护

构建版本：`arena-gdist-runtime-2-capacity-safe`。物理时钟、HS/PT/RS 规则、资产范围和距离定义保持不变。计算仍采用 gDist BVTT 与原作者的 `TriDistPQP` 三角形表面距离。

## 问题与修复

旧版本的 GPU 候选队列容量为 4,194,304。Large Scandinavian 的微波炉、烤箱、温度旋钮短流程中，508 × 62,230 三角形的某些查询产生超过容量的候选，导致整个提交批次返回缺测；错误列出的首条关系不一定是真正触发溢出的网格对。

新版本在展开前计算候选数量的上界，必要时降低一次展开的深度。若单层展开仍可能超过容量，则对当前完整候选集合中的所有三角形对直接执行 `TriDistPQP` 并取最小值。既不截断候选，也不返回包围盒距离。队列容量保持不变；串行和多 CUDA 流入口使用同一容量保护。异常退出前等待已经提交的流结束，防止下次复用仍在运行的缓冲区。

首个未发布候选直接调用作者的 slow narrow 路径，在实际烤箱网格中得到 0.35947904 m，而完整三角形对穷举为 0.35921383 m。该候选被拒绝。第二版完成候选集合时不使用该路径中的 `raw_distance_simple` 排除条件，直接计算剩余三角形对；通过后才安装。

## 已核对的证据

- 容量 256 的隔离 GPU 构建：20 个案例，包含不同网格大小、非单位变换、分离/相交平面，以及 1/4/7 路并发和重复调用。与完整三角形对分块穷举一致；实际触发 104 次容量结束路径，其中 32 次两棵树深度不同。
- 三个真实失败场景导出的 56 组网格/位姿：安装后的二进制与完整三角形对穷举结果差值均为 0（本次浮点结果）。这不意味着对所有几何具有无限精度。
- 原版本的两组唯一失败输入在新版本中分别得到 0.29098913 m、0.35921383 m；独立单对查询约 0.73 ms、0.67 ms。该数字不代表整帧或采集耗时。
- 三项场景首个原失败时刻，各 4,310 条距离关系、119 对 RS 检查均无几何缺测。完整 11 项操作上下文检查以 `task_suite_validation_status.json` 的最新记录为准。

真实夹具网格、历史原始记录和视频不放入 Git。远端证据目录为运行数据根下的 `gdist_candidate_review_20261024`；`original_pair_check.json`、`candidate_v2_pair_check.json`、`installed_pair_check.json` 保留了原失败及对照结果。

## 可复现的隔离检查

在项目配置好的 CUDA/Python 环境运行：

```bash
python scripts/verify_gdist_capacity.py --output /absolute/new-capacity-check
```

输出目录必须不存在。检查器核对当前源码与安装二进制的身份，从已记录编译命令生成容量 256 的独立二进制，再运行精确距离对照。它不会替换安装版本、降低正式队列容量、修改风险阈值或启动仿真采集。CPU 队列检查不能代替此 GPU 检查；合成检查也不能代替新场景的实际关系验证。

## 历史数据

构建脚本在替换前按二进制 SHA256 将旧 `gdist_native.so` 和 `build_info.json` 保存到 `runtime/gdist/history/<sha256>/`。历史数据仍需在独立源码目录中使用自己的冻结实现、旧二进制和原元数据；不能直接用新后端覆盖历史评价。新采集冻结新的构建身份。显式重算必须另建输出并记录迁移。

注意：碗入水槽 seed43 的 `ik_reachable` 仍失败，并使用原生备用摆放；因此它是几何/评价链路验证与失败布局诊断，不是可执行任务布局或任务成功验收。
