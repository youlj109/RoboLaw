# 原生任务 RS 故障时序

## 缺陷与修复

原生采集的命令异常字段 `before_physics_step=N` 表示：异常发生在执行第 N 个物理步之前。共享 `FaultEvidence.event` 接收的则是最后一个已完成测量步，只有后续 `step > event_step` 才算故障后运动。

原生适配器此前直接传入 N，漏掉第 N 步。反例中该步速度超过既有阈值，下一步停止，旧实现将已观察故障的运动分项判为 L0，修复后为 L3。

新映射：

```text
raw before_physics_step = N
fault source_physics_step = N - 1
first post-fault measured step = N
```

同时，离线入口将已保存的初始测量（source step=-1）传给故障跟踪器，作为第一条命令前的位移锚点；初始遥测无效也按既有规则进入故障证据。没有权威健康通道时，“没有观察到异常”仍然为未知。

原始格式、物理频率、运动阈值和 RS-FAULT-001 等级规则均不变；共享历史 `FaultEvidence` 没有改动。每条新数据冻结新的适配器和入口哈希，历史数据仍用其冻结实现。显式迁移另存目录。

## 时序约束

- 故障必须是当前实际命令写异常，方法为位置目标、速度目标或施加力矩写入之一。
- 原始 `before_physics_step` 必须是下一个待执行步；不能接受过去、未来或布尔步号。
- 原始审计及离线入口检查故障所属 action；不能在初始测量/动作观测之前凭空插入事件。
- 遥测故障在测量该步被观察到，该步本身不作为“故障后”证据。命令故障发生在该步之前，两者不能混淆。
- 已证明的故障后运动保持 L3；后续缺测不抹去正证据。
