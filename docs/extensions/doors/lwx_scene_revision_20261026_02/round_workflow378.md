# 固定场景、单项修改、按轮推进

本聊天用户依据游博截图明确采用的方式，适用于本轮 C04 human 和 C06 human。已完成的 C04 property 保留，不重采；不恢复定时任务。

## 每轮规则

1. 冻结用户批准的场景、人体姿态和安全阈值。
2. 每项提出一个有证据支持的修改假设，写下预期、固定条件和判据。
3. 预先声明规划 seed 列表；当前为 42、43、44。同目标、同策略比较障碍开关。
4. 每项执行一次预定验证，失败保存原因、输入和输出，转下一项。轮内不扫参数、不不断追加重试。
5. 轮末统一复盘；已通过结果保留，共同原因集中修复，未解决项进入下一轮。
6. 规划轮内不穿插额外物理试验。确定候选后，单独进行交付必需的真实执行和独立验收；失败也不在验收脚本里自动调参。

“一个修改”按一个清晰假设计数：一次缓存修正可以涉及几处代码，但不顺便改变抓点、人体位置和控制参数。输入缺失、脚本未进入候选计算等运行错误另记，修复检查入口时不能借机更换候选。

## 为什么适合当前任务

- 单个失败任务不再无限占用整轮时间，其他任务先获得验证机会。
- 固定场景和配对条件，使结果能追溯到本轮修改，减少基线失配和场景反复确认。
- 低成本规划与昂贵的仿真采集分阶段，临时候选不必反复生成视频和全套物理报告。
- 每次失败留下可复用证据，避免换名字后重复同一种失败。
- 最终通过仍需要真实接触开门、匹配基线、中性对照、原安全距离、接触因果、门扫掠、自碰撞、限位、配对规划与视频。

模型训练可固定数据、模型和评测集，只改一种训练策略；机器人抓取可固定场景与初态，只改接近或闭合策略；网络排障可固定请求与机器，一次验证一个代理／路由假设；批量构建可逐项目一次修复与一次构建，轮末归纳共同错误。

批量推进提升吞吐，单项修改提高归因清晰度。跨变量的相互作用在后续轮次以一个明确的组合假设验证。截图的二十分钟属于那批规划，不能直接当作真实接触和完整验收的耗时承诺。
