# 11 场景安全抓放采集规范

本文是远程机器的实施规范：采集 **11 个场景，每场景 200 条合格轨迹，共 2200 条**，最终交付 **LeRobot v3** 数据集。这里只规定范围、随机化、采集与验收，不触发本机采集。最终数据字段和交付组织见 [数据输出格式](data_output_format.md)。

## 1. 任务与场景范围

所有场景执行同一任务：机械臂抓住芥末酱瓶的瓶身，完成接近、闭爪、抬升、绕障运输、入碗下放、松爪、撤离和落稳。场景组成固定为 **6 个财产安全＋4 个机械臂自身安全＋1 个人手安全**。

人手场景只使用 `human_default_mpfb`，即原默认 MPFB 人体模型和伸手姿态，手臂伸入瓶子到碗的操作区域。远端调度必须显式选择下表中的 11 个 ID，不能根据历史封装脚本的默认场景集合扩大范围。每个 ID 独立达到 200 条；一个场景多采的数据不能抵扣另一个场景的缺口。

## 2. 逐场景随机化范围

`U(a,b)` 表示均匀采样。所有位姿扰动相对于各场景原始布局：X、Y 两轴分别独立采样，yaw 为绕竖直轴的角度扰动。瓶与碗分别采样，障碍独立采样。表中的 ± 范围不是圆形半径。初始化 Z、roll、pitch 不随机；物理静置后的实际位姿另行记录。

所有场景的共同材质对象是厨房墙面、台面、柜门和目标碗的允许修改表面。表中“颜色乘数”均指 RGB 三通道分别采样后乘以原颜色，并截断到 `[0,1]`；粗糙度是视觉参数，不是物理摩擦。每个材质组共享一次采样结果，每条轨迹内保持不变。

红酒杯、横杆、窄门、尖角设备这四个困难场景只将物体和障碍的 **XY、yaw 几何范围减半**。灯光与材质范围不减半，也不随失败率自动缩小几何范围。

两盏灯分别为 `/World/Light` 和 `/World/DirectionalLight`；只改变强度乘数与色温，安装位置和朝向不变。材质修改沿用现有允许名单，仅作用于可直接写入的 `OmniPBR`／`UsdPreviewSurface` 表面。透明材质、贴图连接颜色、标签、显示屏、控制按钮和安全标识受保护。芥末酱瓶的共享瓶身／标签纹理保留，不对其改色。采样参数与实际应用记录必须分别保存，不能把采到障碍材质参数误报为人体或透明玻璃已改色。

## 3. 保持固定的内容

- 原机器人模型、机器人基座、厨房布局、台面高度；不增加新物体或替换场景模型。
- 瓶、碗、障碍物的尺寸、质量、摩擦、碰撞几何和其余物理属性；不通过改小障碍或改变摩擦提高成功率。
- 原 DROID 两个外相机和一个腕相机：安装关系、内参、分辨率 1280×720 固定；外相机不移动，腕相机随末端运动，逐帧保存实际相机位姿。
- 物理频率 120 Hz，动作及 RGB 15 Hz；动作保持 7 维绝对机械臂关节目标和 1 维二值夹爪目标。
- 既有速度、加速度、碰撞检查、携瓶倾角、支撑松爪及最终落稳条件。人体规划间距 4 cm、执行间距 2 cm 和携瓶执行硬限制 28°保持不变；规划偏好不能替代执行硬限制。

默认人体是静态碰撞障碍。随机化作用于整个人体根变换，**不是手指、手腕、肘或其他关节角随机化**；局部骨架、网格、体型和伸手姿态固定。根 yaw 会使远离根部的手掌产生额外位移，因此 ±1 cm 不是手掌世界位移的上限。每条轨迹内人体不主动运动，世界关键点应随采样后的根变换更新。

## 4. 远程机器的实施步骤

现有实现基于 Arena、Isaac Lab、USD、cuRobo 和 FCL，部署依赖见 [INSTALL.txt](../INSTALL.txt)。远端先配置实际资产路径、运行环境、设备和存储位置，再实施下列流程；本文不提供绑定本机容器或本机数据目录的启动命令。

1. **确定场景和配置。** 非人体十项使用 [augmentation_nonhuman10.json](../configs/augmentation_nonhuman10.json)；默认人体使用 [augmentation_human7.json](../configs/augmentation_human7.json) 中的数值范围，但只选择 `human_default_mpfb`。后者文件名为历史命名，不改变本规范的单个人体场景范围。非人体抓取／运输设置参考 [reproduction_presets.json](../configs/reproduction_presets.json)，该文件没有默认人体的专用记录，不能把其他人体记录自动套用给它。默认人体参数单独见下文。
2. **配置配额与资源。** 现有批次入口是 [collect_obstacle_library.py](../scripts/collect_obstacle_library.py)，每 ID 合格目标设为 200，并明确实际 ID 列表、主种子、尝试预算、输出目录及 RGB 记录。尝试预算是累计尝试数，应足以覆盖成功目标与失败尝试；达到预算仍不足时报告缺口。批量物理执行、RGB 渲染及 CPU 验证的并行度由远端资源决定，不因并行执行改变轨迹内容或验收条件。
3. **设置完整执行时限。** 远端环境时限设为 180 秒，动作上限保留 2400，初始化另占 8 个环境步。180×15＝2700 步可覆盖 2400＋8 步；仅延长环境时限，不加快动作或跳过阶段。环境提前超时应记录为失败，不能把截断轨迹当完整成功。
4. **采样并落盘。** 按主种子、场景 ID、尝试编号生成独立的几何、外观、规划种子；先保存 `episode_spec.json`，再将同一采样布局用于物理、cuRobo／FCL 世界和渲染。场景选择或执行顺序不改变同一 ID／attempt 的采样结果。
5. **检查初始布局并重新规划。** 物体静置后读取实际位姿，检查支撑、倾倒、初始穿插和碰撞几何。基于当前瓶碗位置完成瓶身抓取和全流程规划。规划提示只能提供候选，必须通过当前场景的完整碰撞与携瓶检查；不平移旧关节轨迹来代替重规划。
6. **执行并保存中间数据。** 记录每个动作前后的状态、接触、安全检查和阶段信息。三路 RGB 与 `obs[t]` 对齐，即对应执行 `action[t]` 之前的状态。记录式渲染必须恢复实际执行状态，不能重新模拟一条相似轨迹替代原轨迹。
7. **验收后累计。** 完整物理抓放、数据完整性、独立安全审查和场景风险作用均通过后，该条才进入该 ID 的接受集合。失败保留原尝试编号与原因，继续采样到各 ID 达到 200 条或明确耗尽预算。
8. **导出最终数据。** 将接受集合转换为 LeRobot v3，并完成该格式的读取和时间对齐验证；具体字段与交付检查见 [数据输出格式](data_output_format.md)。

同一配置续采应恢复已有尝试及接受集合，避免覆盖轨迹或重复计数。更改随机范围、主种子、抓取／运输设置、环境时限或运行配置时使用独立批次目录。新目录使用相同主种子和相同 ID／attempt 会复现同一采样布局，不能把这种重跑误算为新增的独立随机样本。

默认人体的起始抓取／运输设置沿用 [现有人体封装脚本中的参数](../scripts/collect_human_augmentation.sh)：`placement_strategy=lower-first`，抓取 tilt/yaw 为 35°/0°，抓取 offset z/y 为 0/−0.01 m，运输瓶高为 1.11 m，启用 `supported_release`，运输倾角 cap 为 25°。25° 用于规划与路径修正的余量控制，28° 仍是物理执行硬限制，二者不能互相替代。远端需验证这些设置在默认人体及采样布局上完成完整抓放，再扩大采集；脚本中的历史 ID 列表与数量不属于本次范围，不能直接照搬。

## 5. 合格轨迹与场景资格

每条计入 200 条配额的数据须同时满足：

- 完成瓶身抓持、稳定携带、入碗支撑、松爪、撤离及最终落稳；没有提前超时或掉落。
- 原物理执行检查和独立碰撞／间距审查通过，人体与其他障碍的原安全约束保留。
- 三路图像帧数与动作数一致，全部图像可解码，状态链连续，相机参数、逐帧位姿和动作前图像对齐正确。
- 障碍确实具有该场景规定的风险作用。财产场景检查携瓶运输，自身安全场景可涉及接近、运输或撤离；钢夹保留已有侧向风险判定，不额外强制其阻断起终点直连。默认人体保留原有场景资格判定。

风险作用的直连参考只做几何查询，不执行碰撞动作。`obstruction_unconfirmed` 即使物理、RGB 和独立安全审查通过，也不计入配额；采样无效、规划失败、物理失败、数据失败、场景资格未确认分别统计，不能通过重新标记或放宽约束补足数量。

## 6. 原生数据、最终格式与交付统计

**当前 collector 原生输出是 H5 等中间数据，不是 LeRobot v3。** 其中包括 `trajectory.h5` 的动作／状态／阶段、`rendered/images.h5` 的三路图像，以及采样配置、实际外观、物理结果和验收记录。这些中间数据需要保留到导出校验完成，以便追溯每条最终 episode 的原始来源。

最终交付必须是可由 LeRobot v3 对应读取器加载的数据集。使用 [独立 CPU 环境](../scripts/setup_lerobot_export.sh) 和 [导出入口](../scripts/export_safety_lerobot_v3.py)，读取 collector manifest 中的正式接受集合，并按原生格式写入表格、三视角视频、统计和 episode 元数据。已有无叠字原视角 MP4 可直接复用；只有 RGB 时，导出器从 JPEG 编码三路训练视频，无须为全部轨迹生成四路预览。具体命令及验证报告见 [数据输出格式第 7 节](data_output_format.md#7-从现有采集结果导出)。

物理成功、RGB 完整且安全复核通过，但标记为 `obstruction_unconfirmed` 的默认人体数据可通过单独成功清单导出，其原资格标记会保留。这类成功数量与本规范要求的正式 benchmark 配额分别统计，不能因 LeRobot 文件可读就改写场景资格。

交付清单逐 ID 列出合格数、尝试数、各类失败数、缺口、源轨迹路径与最终 episode 映射，并报告采样参数和接受参数分布。完成条件是表中 11 项各 200 条、合计 2200 条，且转换后数量、三视角帧数、动作／状态含义和时间对齐保持一致。任何缺口都应如实报告，不能以总数充足替代逐场景达标。
